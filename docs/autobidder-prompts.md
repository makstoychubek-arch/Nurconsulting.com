# Промпты для Cursor — внедрение автобиддера в NR Space

Порядок обязателен. Каждый шаг — новый чат в Agent-режиме. Перед стартом: положить `NR_Space_Autobidder_Architecture_v2.md` в репо как `docs/autobidder.md`.

---

## 0. Правило для `.cursor/rules/autobidder.mdc` (создать один раз)

```
---
description: Правила для модуля автобиддера
globs: supabase/**, src/**/adv/**, src/**/autobidder/**
alwaysApply: true
---
- Источник истины по архитектуре — @docs/autobidder.md. Не отклоняться без явного запроса.
- Эндпоинты WB Advertising API брать ТОЛЬКО из docs/autobidder.md раздел 2 или из официальной OpenAPI-спеки WB "Продвижение". Не выдумывать пути, параметры и поля ответов. Если чего-то нет — остановиться и спросить.
- Все таблицы, функции и запросы — с cabinet_id. RLS с первого шага. Токены — только Supabase Vault, в таблицах хранить только secret_id.
- Любая запись ставки в WB проходит через флаг DRY_RUN (env). При DRY_RUN=true — только лог в bid_history с applied=false, без вызова WB.
- Не менять существующие Edge Functions, кроме WB proxy, без явного запроса.
- В конце каждого ответа: (1) список созданных/изменённых файлов, (2) команды для применения, (3) что проверить руками.
```

## Шаг 2 — Прокси `/adv/*`

```
Прочитай @docs/autobidder.md раздел 2 и 11.3. Открой существующую WB proxy Edge Function (укажи путь: ___).

Добавь в неё неймспейс /adv/* для рекламного API WB (хост advert-api.wildberries.ru):
- Вход: cabinet_id + относительный путь + метод + body. Токен достаётся из Vault по cabinets.adv_token_secret_id, на фронт никогда не возвращается.
- Throttle на токен (очередь, не более N req/min — N вынести в env, дефолт возьми из OpenAPI-спеки WB, если там указан; иначе 5 req/min и пометь TODO).
- Retry с экспоненциальной задержкой на 429 и 5xx (макс 3 попытки).
- На 401/403: update cabinets set adv_token_valid=false, adv_token_checked_at=now(); вернуть структурированную ошибку.
- Типизированные хелперы: getAdverts, listClusters, getBids, setBids, getClusterStats, getClusterStatsDaily, getMinus, setMinus, fullstats, pause, start — по путям из раздела 2. Для setBids — обязательная проверка флага DRY_RUN: если true, не вызывать WB, вернуть {dry_run:true, payload}.

Напиши тесты с моками для getBids, setBids (оба режима DRY_RUN) и обработки 401. Не выдумывай поля ответов WB: если структура ответа неизвестна — типизируй как unknown и оставь TODO с ссылкой на спеку.
```

**Проверить:** вызов `getAdverts` на одном реальном кабинете возвращает список кампаний; на кабинете с испорченным токеном ставится `adv_token_valid=false`.

```

⚠️ Самый ответственный шаг. Сначала попроси план и тест-кейсы, затем код.

Обязательно покрой: позиция хуже диапазона; лучше диапазона; в диапазоне; NULL позиция (не найдена в выдаче); упор в max_bid; срабатывание hysteresis; исчерпан бюджет кабинета; исчерпан бюджет группы; невалидный токен одного из кабинетов. Уточни, что тебе непонятно в документе, прежде чем писать код.
```

**Промпт 4b (код), после согласования плана:**
```
Реализуй autobidder_tick по согласованному плану и тест-кейсам.

Требования:
- Обход кабинетов параллельно, правил внутри кабинета последовательно.
- get_ad_position(nm_id, cluster_key): чтение публичной поисковой выдачи WB по запросу cluster_key, поиск своего nm_id среди рекламных позиций. Формат ответа эндпоинта — вот JSON, снятый мной в DevTools: [ВСТАВИТЬ]. Если не вставлен — оставь функцию-заглушку с TODO, не выдумывай формат.
- Способ A (fetch_auction) — заглушка, возвращает null.
- Стратегия только min_sufficient. Параметры step_pct, hysteresis, min_bid_floor, max_bid — из правила.
- Бюджеты по 11.5: расход за сегодня из adv_daily_stats + оценка bid×impressions/1000 с последнего синка.
- Каждое решение → bid_history (source='feedback', applied по DRY_RUN). Каждое измерение → serp_position_snapshots.
- pg_cron */5 мин. Ручной HTTP-запуск для одного rule_id — для отладки.

```

## Общие правила работы с Cursor на этом проекте

- Один шаг = один чат. Не просить "сделай следующий шаг" в том же чате — начать новый и снова сослаться на @docs/autobidder.md.
- Если модель предлагает эндпоинт, которого нет в разделе 2 — остановить и попросить показать источник.
- Шаги 4, 7, 9 — сильная модель или режим "план → код". Шаги 1–3, 5, 6, 8 — Grok справится.
- До `DRY_RUN=false` — минимум 7 дней логов на одной кампании.
- После каждого шага коммит с тегом `autobidder/step-N`, чтобы откатываться по шагам.
