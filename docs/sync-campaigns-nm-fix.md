# Итог: `nm_id` в sync-campaigns + фокус без Zevina 2

09.09.2026.

## Почему было 0 кампаний

`GET /api/advert/v2/adverts` **не кладёт** `nms` / `nmId` на верхний уровень. Карточка в **`nm_settings[].nm_id`**.

Старый код брал только `nms` / `nmId` и молча делал `continue`. Проверено на Zevina 1: 475 кампаний в ответе, 449 с `nm_settings`.

Дополнительно: `listClusters` ждёт `{ items: [{ id }] }`. Старое тело `{ advertId }` давало 400.

## Что сделали с `nm_id` (не отдельный detail-запрос)

Не гоняем adverts detail на каждую РК — тот же v2 `?ids=` тоже без `nms`, зато **`nm_settings` уже есть в списке**.

Порядок:

1. `nm_settings[0].nm_id`
2. старые поля `nms` / `nmId`
3. ведущие цифры из имени (`287679331 Поиск…`)
4. если ничего нет — кампания **всё равно пишется**, `nm_id = NULL` (колонка стала nullable)

Тик кампании без `nm_id` пропускает (ставки без карточки не ставим).

`nm_id` nullable, чтобы 26 кампаний Zevina 1 без `nm_settings` не выкидывать.

## Zevina 2: почему не `adv_token_valid=false`

| Вариант | Минус |
|---|---|
| `adv_token_valid=false` | В командном центре это «токен сдох / 401». Позже `check_tokens` и алерты спутают с реальной поломкой. Секрет как будто мёртвый. |
| Хардкод имени в функциях | Легко забыть второе место, путаница при переименовании. |
| Удалить secret | Просили не делать. |

**Сделали:** `cabinets.adv_enabled` (default `true`). У Zevina 2 = `false`.  
Токен и `adv_token_secret_id` на месте. Джобы `sync-campaigns`, `sync-daily-stats`, `autobidder-tick` берут только `adv_enabled=true`.  
Вернуть в работу: `update cabinets set adv_enabled = true where name = 'Zevina 2';`  
Ручной обход: `{"force":true}` в теле sync.

Фокус: Baza, Elium, Zevina 1.
