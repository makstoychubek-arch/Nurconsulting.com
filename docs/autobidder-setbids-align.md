## 1. Убрали лишнее поле `bid`

Схема v1 `POST /api/advert/v1/normquery/bids` допускает только:

- `advertId`
- `nmId`
- `normQuery`
- `bidMinorUnits`

Поля `bid` в схеме нет (это v0). Тик больше его не кладёт.

Было: `bid: decided.newBid` + `bidMinorUnits: decided.newBid * 100`.

## 2. Сверка `newBid * 100` с `cpmStep`

Перед отправкой минорные единицы поднимаются вверх до кратного `cpmStep` из `GET /api/advert/v1/config`.

Спека setBids v1 прямо говорит: допустимый шаг — в ответе config.

- `cpmStep` — шаг CPM в **минорных** единицах (0,01 валюты кабинета).
- Пример спеки UZS: `cpmStep: 100000` → 420 × 100 = 42000 не на сетке, уходит 100000 (1000 сум).
- Для KGS шаг скорее 100 (= 1 сом). Тогда 420 × 100 = 42000 уже на сетке, сверка — no-op.
- Config нет / не распарсился → шаг **100** (как раньше: `newBid * 100`).
- 401/403 на config — тот же `token_invalid`, тик кабинета стоп.

Кэш **на кабинет** (`cabinetId`), TTL **60 с** — лимит WB **1 запрос / мин**.  
Тик зовёт `loadAdvConfig` **один раз** в начале `tickCabinet`, если есть правила. Не на каждую кампанию и не на каждый кластер.

`*/5` cron: один GET на кабинет раз в 5 мин — в лимит укладывается. Кэш нужен, если isolate тёплый и тик дернули дважды за минуту, или если позже появятся ещё вызовы.

Пишущие тесты: `alignMinorToCpmStep` / `alignMajorToCpmStep` в decide; `loadAdvConfig` — второй вызов того же кабинета в пределах TTL не бьёт в fetch.

## GET `/adv/v1/budget` — по спеке, без похода в WB

**Бюджет конкретной кампании, не кабинета.**

Из дампа `docs/wb-openapi-promotion.md`:

| | |
|---|---|
| Заголовок | «Бюджет кампании» |
| `operationId` | `getV1Budget` |
| Обязательный query | `id` — **ID кампании** (advertId) |
| Что возвращает | `{ cash: 0, netting: 0, total, currency }` |
| `total` | бюджет **этой** кампании в базовых единицах валюты аккаунта продавца |
| `cash` / `netting` | всегда 0, «поле не используется» |
| Ошибка 400 | `CampaignNotBelongSeller` — «кампания не принадлежит продавцу» |

Текст метода: возвращает бюджет кампании — максимальную сумму затрат **на кампанию**. Бюджет кампании можно пополнить соседним `POST /adv/v1/budget/deposit` — там тоже обязательный query `id` = ID кампании.

Кошелёк **кабинета** (счёт Продвижения + баланс взаиморасчёта + бонусы) — это другой метод: `GET /adv/v1/balance`. В его описании WB прямо пишет: информацию о бюджете кампаний смотреть в `getV1Budget`.

Для §11.5 архитектуры (`org → cabinet_group → cabinet → campaign`) этот эндпоинт **не заменяет** наши лимиты:

- дневной потолок кабинета / группы — наши колонки `cabinets.adv_daily_budget_cap` и `cabinet_groups.adv_daily_budget_cap`;
- расход тик уже берёт из `adv_daily_stats` за сегодня;
- `GET /adv/v1/budget` — это потолок конкретной РК внутри кабинета WB (сколько залито на advertId), не сумма по кабинету и не дневной cap.

Если позже понадобится не упереться в пустой бюджет РК до нашего cap — звать `getV1Budget?id=<wb_campaign_id>` по кампании, не один раз на кабинет.
