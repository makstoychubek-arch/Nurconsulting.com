# Дашборд и РНП не думают при входе

При F5 и повторном заходе цифры уже на экране. Сеть не дергается, пока кэшу меньше трёх часов.

## Дашборд

Последние KPI пишутся в `localStorage` (`nr_dash_paint`, `nr_dash_v1_<кабинет>_<даты>`). Ранний скрипт подставляет их до загрузки приложения — карточки не мигают «—».

`loadFromDB` сначала рисует кэш. Если ему меньше 3 часов, RPC, реклама и финотчёт WB не вызываются. Через 3 часа (и при возврате на вкладку, если кэш протух) данные обновляются сами и перезаписывают кэш. Кнопки «Синхронизировать» / «Обновить» всегда идут в сеть.

Смена кабинета сначала показывает кэш нового кабинета, а не пустые прочерки.

## РНП

Утренний `rnp-morning-fill` уже лежит в базе. При F5 лист берётся из снимка (`rnp_shell_…` + IndexedDB `nr-rnp-lock` / `shell`). Артикулы и дневные цифры лежат в store `data` той же базы.

`openMain` после обновления страницы не форсирует загрузку. `_renderMain` рисует сразу из persist или оставляет уже нарисованный лист. Запрос в Supabase идёт в фоне, только если данных нет или им больше 3 часов. Уведомление «РНП обновлён» на таком фоне не спамится.

Открытие вкладки РНП не должно «думать» несколько секунд: таблица уже на месте.
